# المالية — نور

ينفّذ القسم متطلبات العمل دون اتصال، كشوف الحساب والشيكات، المحفظة والإيصالات، والفواتير والمرتجعات. هو نموذج أولي يعمل محليًا ويتصل اختياريًا بخادم الشركة؛ لم يُعتمد لتشغيل مالي إنتاجي.

## التشغيل والتجربة
ثبّتي Node.js ثم npm ci وشغّلي npm run web للابتوب، أو npm start للموبايل. اختاري محاسب من شاشة الأدوار. تتوفر أيضًا ملفات Start-DARB.cmd وStart-DARB-Mobile.cmd لتشغيل Windows، وتعمل مع Node المثبّت بالنظام أو النسخة المحلية الاختيارية تحت .tools المستبعدة من Git.

للعرض المرتّب: المالية ← المزامنة ← بدء سيناريو عرض مالي جديد. ينشئ زبونًا واحدًا وطلبية 100 شيكل في مساحة محلية مستقلة، ويحافظ على بيانات الحساب السابق وعملياته المعلّقة. زر العودة إلى بياناتي السابقة يرجع إليه. [خطوات السيناريو الكامل](../../../FINANCE-DEMO.md).

## سلوك الحسابات
- كشوف الحساب: اختيار زبون بالبحث، مدين/دائن، فلترة تاريخ ونوع وحركة، وتصدير PDF/طباعة. الرصيد يشمل كامل الحساب، وإجماليات الفلترة تخص الحركات الظاهرة.
- التحصيل: نقدي، دفعة رقمية تمت خارج التطبيق، أو شيك. مراجعة قبل التأكيد وسند قبض وواتساب بإجراء المستخدم. التطبيق لا ينفّذ تحويلًا بنكيًا.
- الشيك: الاستلام يحجزه قيد التحصيل دون تخفيض الذمة أو زيادة النقد. تأكيد الصرف يخفض الذمة مرة واحدة. المرتجع لا يخصم.
- المحفظة: عهدة نقدية لكل محصّل وتسليم نقد للشركة دون تجاوز العهدة. التحصيل الرقمي منفصل.
- الفاتورة: واحدة لكل طلبية غير ملغاة؛ إصدارها يضيف الدين. مجرد تسجيل طلبية لا يضيفه. القوائم مقسّمة إلى غير مصدرة ومصدرة مع بحث وصفحات.
- المرتجع: الفاتورة تحدد السعر والمبلغ؛ السبب والصورة مطلوبان. النموذج يوضح النواقص فوق زر المراجعة، ويختار فاتورة ذات كمية متاحة.

## أرقام الوحدات والمرتجعات
الفواتير الجديدة الصادرة من المالية تحفظ رقمًا فريدًا لكل وحدة بيع. يظهر تحت عرض الأصناف ويُضمّن بطباعة الفاتورة. يجب تثبيت الملصق على القطعة أو الكرتونة المطابقة قبل التسليم. إدخال الرقم كتابة أو بقارئ يعمل كلوحة مفاتيح؛ المسح بالكاميرا غير منفذ.

الاعتماد التلقائي verification=unit_codes يطابق الفاتورة والزبون والطلبية والصنف والسعر والكمية وأرقام الوحدات. يمنع تكرار الرقم أو استخدام رقم من فاتورة/صنف آخر. الطلبات اليدوية تحجز الكمية والأرقام؛ الرفض يحرّرها والقبول يخصم مرة واحدة. الفواتير القديمة لا تُرقّم بأثر رجعي وتذهب للفحص اليدوي. عميل قديم يرسل sales_record ينتج طلبًا معلقًا دون خصم؛ الاعتمادات التاريخية لا تنعكس أو تتغير.

مطابقة الرقم ليست فحصًا ماديًا للحالة أو كشفًا لنسخ الملصق: unitIdentityVerified يدل على مطابقة المعرّف، وphysicalIdentityVerified يبقى false. الصورة ليست إثباتًا آليًا للمصدر.

## الربط بالخادم والحفظ دون اتصال
1. انسخي .env.example إلى .env واضبطي أسرار Docker محليًا؛ لا تُرفعي .env أو .local.
2. شغّلي Docker Desktop ثم docker compose -p darb up -d --build --wait. الهجرات تُنفذ عند تشغيل الخادم.
3. لحساب موجود، شغّلي أمر permissions:provision الموثّق في server/README.md لشركة محددة. لا تمنح الهجرة صلاحيات تلقائيًا.
4. المالية ← المزامنة ← ربط حساب الشركة: رابط الخادم، رمز الشركة، البريد وكلمة المرور. على اللابتوب الرابط http://localhost:3001؛ الهاتف يحتاج عنوان IP للجهاز وCORS مناسبًا.
5. ينفصل التخزين لكل شركة ومستخدم. الرمز في sessionStorage على الويب وSecureStore على الجهاز؛ كلمة المرور لا تحفظ. إعادة فتح المتصفح بالكامل قد تتطلب تسجيل دخول جديد.
6. العملية تُحفظ محليًا قبل إشعار النجاح، وتُرسل عند الاتصال. تظهر بانتظار المزامنة ثم تمت المزامنة بعد قبول الخادم. الأخطاء الدائمة توقف الطابور لتراجعها المستخدمة، ولا تُحذف تلقائيًا.

الخادم يعيد التحقق من المستخدم والصلاحيات والشركة، ويتحقق من البيع داخل قفل ومعاملة للشركة. البيانات والحساب والسجل التدقيقي تُحدّث معًا. UUID ثابت يمنع تكرار الخصم، وسحب العمليات المقبولة يعالج ضياع الرد بعد نجاح الخادم.

للتهيئة التطويرية الاختيارية، server/prisma/seed-finance-dev.ts يحتاج NODE_ENV=development وDARB_FINANCE_SEED=1 وإعدادات JSON من stdin (companySlug, email, password). ينشئ شركة وهمية وحسابات محددة دون إعادة ضبط حسابات موجودة. أي ملف اعتماد محلي تحت .local لا يُرفع.

## الصلاحيات والحدود
المدير/المحاسب يديران المالية، والمندوبان يسجلان التحصيل، والمستودع يراجع المرتجعات فقط حسب الصلاحيات الفعلية. returns:create للمدير والمحاسب ومندوبي البيع والتوصيل، وreturns:review للمدير والمستودع. لا يقبل الشخص طلبه اليدوي بنفسه. اختيار دور من واجهة التجربة لا يمنح صلاحيات خادم.

الحفظ دون اتصال متاح بعد تحميل التطبيق؛ إعادة فتح الويب من الصفر دون اتصال تحتاج نسخة مثبتة/تخزين تطبيق غير منفذ هنا. بقية ميزات الخريطة وغيرها تحتفظ بمصادر بياناتها الحالية. لا يُعتبر القسم بديلًا معتمدًا لنظام محاسبة أو فاتورة ضريبية.

## الفحوص
npm run typecheck وnpm test للتطبيق. داخل server: npm run build وnpm test. اختبار التكامل يتطلب خدمات DARB الحقيقية ومفتاح DARB_INTEGRATION=1؛ راجعي server/README.md. [نتائج التحقق](../../../FINANCE-VERIFICATION.md).
